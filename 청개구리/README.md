# 청개구리 🐸 — 비가 오면, 혜택이 쏟아진다

날씨 기반 오프라인 매장 할인·예약 플랫폼 MVP (Phase 1).
비 오는 지역에서 점주가 정한 우천 할인이 열리고, 소비자가 예약하고, 점주가 QR로 방문을 확인한다.
태풍 때는 위험 시간 예약을 막고, 태풍 전·후 안전한 시간만 특가로 연결한다.

> 원본 요구사항: [개발-프롬프트.md](개발-프롬프트.md) · 요구사항 분석·핵심 결정: [docs/01-요구사항-분석.md](docs/01-요구사항-분석.md)

## 구성

```
청개구리/
├─ apps/
│  ├─ mobile/   소비자 앱 — Expo SDK 58 + React Native 0.88 + Expo Router (iOS/Android/웹 미리보기)
│  └─ web/      Next.js 16 — 점주 관리자(/owner), 플랫폼 관리자(/admin), REST API(/api/v1/*)
├─ packages/
│  ├─ core/            순수 도메인 로직: 날씨 상태 머신, 할인 엔진, 예약 상태 규칙 (테스트 62개)
│  ├─ server/          DB(마이그레이션·PGlite/Postgres), 인증, 서비스, 날씨 어댑터 (테스트 48개)
│  └─ design-tokens/   브랜드 색상·간격 토큰, 개굴이 캐릭터 도형 데이터(웹·앱 공용)
└─ docs/               설계·API·DB·배포·법률 검토·운영 문서
```

## 빠른 시작 (로컬)

필요: Node.js 20 이상 (개발 환경: Node 26.13.1, npm 11.20)

```bash
npm install          # 저장소 루트에서 1회
npm run db:reset     # 로컬 DB(.data/pglite) 초기화 + 샘플 데이터 (웹 서버가 꺼진 상태에서)
npm run dev:web      # http://localhost:3000  — 점주·관리자 웹 + API
npm run dev:mobile   # http://localhost:8081  — 소비자 앱 웹 미리보기 (다른 터미널)
```

- 실기기에서 앱 실행: `cd apps/mobile && npx expo start` 후 Expo Go 로 QR 스캔. 앱은 Metro 호스트 IP의 3000 포트 API 를 자동으로 사용한다 (`EXPO_PUBLIC_API_URL` 로 변경 가능).
- PGlite 는 한 프로세스만 열 수 있다. `db:reset` 은 웹 서버를 끈 뒤 실행한다.

### 개발용 샘플 계정 (로컬 DB 전용, 비밀번호 모두 `cheong1234`)

| 역할 | 이메일 | 비고 |
|---|---|---|
| 소비자 | user@cheong.dev | 앱 로그인 |
| 점주 | owner@cheong.dev | [샘플] 칼국수(자동 승인)·이자카야(점주 승인)·승인대기 돈까스 |
| 점주 | owner2@cheong.dev | [샘플] 카페 |
| 관리자 | admin@cheong.dev | 매장 승인, 날씨 Mock 시나리오 전환 |

샘플 매장은 부산 동래구 온천장 일대의 **가상 매장**이며 이름에 `[샘플]` 이 붙는다. 온천동은 Mock "비 내림", 부전동은 Mock "맑음"으로 시작한다.

### 시연 시나리오

1. 앱 홈 → 비 오는 온천동의 할인 매장 → 칼국수 → 오늘 18:00 → 메뉴 선택(서버가 가격 계산) → 예약 확정 → QR
2. 웹 `/owner` (owner@) → 예약 관리 / QR 방문 확인 (방문 1시간 전부터 확인 가능)
3. 웹 `/admin` (admin@) → 날씨·지역 → 온천동을 `[MOCK] 태풍 접근 예보` → 앱 홈/태풍 특가 화면 확인
4. `[MOCK] 태풍경보 발효` → 신규 예약 차단, 예약자에게 안전 안내 알림 → `[MOCK] 태풍 특보 해제` → "안전 확인 → 회복" → 점주 "영업 재개" → 회복 특가 예약
