# 배포 가이드 (초기 스타트업 기준 권장 구성)

> 아래는 권장 절차이며 **아직 실제 배포는 하지 않았다** (계정·키 없음).

## 권장 구성

| 구성 요소 | 권장 | 비고 |
|---|---|---|
| DB | Supabase (Seoul 리전) | 같은 SQL 마이그레이션 사용 |
| 웹+API | Vercel (Next.js) 또는 Node 서버(Fly.io, AWS Lightsail 등) | 인메모리 요청 제한은 **단일 인스턴스 기준** → 다중 인스턴스면 Redis 로 교체 |
| 주기 작업 | Vercel Cron / Supabase pg_cron+http / GitHub Actions | 5분마다 `POST /api/v1/jobs/tick` |
| 앱 | EAS Build → App Store / Play Store | `eas build`, `eas submit` |

## 1. Supabase

1. 프로젝트 생성 (리전: Northeast Asia - Seoul).
2. SQL Editor 에서 순서대로 실행:
   - `packages/server/migrations/0001_init.sql`
   - `packages/server/migrations-supabase/9000_rls.sql`
   - (마이그레이션 기록) `create table if not exists schema_migrations (name text primary key, applied_at timestamptz not null default now()); insert into schema_migrations values ('0001_init.sql');`
   - 또는 서버 첫 기동 시 `migrate()` 가 0001 을 자동 적용한다 (RLS 파일은 수동).
3. Connection string(Transaction pooler, 6543) → `DATABASE_URL`. postgres.js 는 `prepare: false` 로 설정돼 있어 pooler 와 호환.
4. 관리자 계정 생성: 회원가입 API 로 계정을 만든 뒤 SQL 로 `insert into user_roles (user_id, role) values ('<uuid>', 'admin');` (가입으로는 관리자를 만들 수 없음).
5. **샘플 데이터(seed)는 운영에서 실행되지 않는다** (코드에서 차단).

## 2. 웹 (Vercel 예시)

- Root Directory: `apps/web`, Install: 저장소 루트 `npm install`, Build: `npm run build -w web`.
- 환경변수 (`apps/web/.env.example` 참고):
  - `DATABASE_URL`, `QR_SECRET`(32자+ 무작위, `openssl rand -base64 48`), `CRON_SECRET`
  - `KMA_SERVICE_KEY` — 없으면 운영 기동이 **거부**된다 (Mock 날씨 오표시 방지). 정말 필요하면 `ALLOW_MOCK_WEATHER_IN_PRODUCTION=true`.
  - `ALLOWED_ORIGINS` — 앱 웹 버전 출처가 있다면
  - `PUSH_MODE=expo` (+ `EXPO_ACCESS_TOKEN` 선택)
- 쿠키는 운영에서 `Secure` 로 설정된다 (HTTPS 필수).
- 서버리스에서는 `PGLITE_*` 를 쓰지 말 것 (DATABASE_URL 필수).

## 3. 주기 작업

```bash
curl -X POST https://<도메인>/api/v1/jobs/tick -H "Authorization: Bearer $CRON_SECRET"
```
5분 간격 권장. (기상청 초단기실황 갱신 주기 1시간, 초단기예보 30분 / 지역당 10분 이상 지난 경우만 호출)

## 4. 앱 (EAS)

1. `cd apps/mobile && npx eas-cli@latest init` → EAS 프로젝트 ID 생성.
2. `app.json` 의 `ios.bundleIdentifier`, `android.package` (현재 `dev.cheonggaeguri.app` 임시값) 를 실제 값으로.
3. `EXPO_PUBLIC_API_URL=https://<도메인>` 설정.
4. 푸시: `npx expo install expo-notifications` → 토큰 발급 후 `PATCH /notification-preferences {pushToken}` 연동 (Phase 2, 현재 미구현).
5. `eas build -p all --profile production` → `eas submit`.
6. 스토어 심사용: 위치 권한 사용 목적 문구(app.json 에 반영됨), 개인정보 처리방침 URL, 계정 삭제 기능(앱 내 탈퇴 구현됨).
