## 2. 실행하지 못한 것과 이유
- **iOS·Android 실기기/시뮬레이터 실행**: 이 PC 에 Xcode·Android 에뮬레이터·실기기 연결이 없음. Expo 웹 미리보기로 화면·흐름을 검증했다. 네이티브 전용 동작(SecureStore, 위치 권한 팝업, 애니메이션 성능)은 미검증.
- **카메라 QR 스캔**: 점주 웹의 카메라 스캔(jsQR)은 카메라가 없어 미검증. 예약번호 입력 방식과 QR 토큰 검증 API 는 테스트로 검증.
- **작은 화면·느린 네트워크·접근성 UX 테스트**: 브라우저 창 크기 조절이 적용되지 않아 모바일 폭 검증을 하지 못했다. 컴포넌트는 최소 터치 영역 44pt·접근성 라벨·로딩/오류/빈 상태를 갖추었지만 실측하지 않았다.
- **기상청·Expo Push 실제 연동**: 키 없음.

## 6. 주요 설계 결정 (변경 시 참고)
- Supabase Auth 대신 자체 세션(해시 저장) — 벤더 종속 최소화, 로컬에서 Docker 없이 전체 실행. 운영 DB 로 Supabase Postgres 사용.
- 점주·관리자를 하나의 Next.js 앱으로 — 배포 대상·권한 코드 단일화.
- 날씨 판정 단위 = 기상청 5km 격자. 비 예보 단계에서는 예약을 받지 않음(알림 신청만).
- 태풍 특가는 "강할수록 할인"이 아니라 "안전한 시간에만 예약 가능" 구조. 영향 시각을 모르면 차단.
