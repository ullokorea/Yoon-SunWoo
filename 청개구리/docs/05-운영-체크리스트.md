# 운영 전 체크리스트

## 기상청 연동 검증 (키 발급 후 필수)
`KmaWeatherAdapter` 는 공개 문서 기준으로 작성했고 **실제 키로 호출해 본 적이 없다.**

1. 공공데이터포털에서 활용 신청: **기상청_단기예보 조회서비스**, **기상청_기상특보 조회서비스** (승인까지 시간이 걸릴 수 있음)
2. `KMA_SERVICE_KEY` 설정 후 서버 기동 → 관리자 > 날씨·지역 > "지금 갱신"
3. 확인 사항
   - [ ] 초단기실황 `PTY`, `RN1` 값이 들어오는가 (`weather_observations.raw`)
   - [ ] 특보 통보문 응답에 `t6`(특보 현황), `t7`(예비특보) 필드가 있는가. 없거나 형식이 다르면 어댑터가 오류를 내고 지역은 30분 후 UNKNOWN(예약 차단)이 된다 → `parseAlertText` 수정 필요
   - [ ] 지역별 `warning_area_code` 설정 (형식 `"<지점번호>:<구역 키워드>"`, 예: `159:부산`). 신규 매장으로 자동 생성된 지역은 비어 있어 **특보 판정 불가 → UNKNOWN** 이므로 관리자가 반드시 입력해야 함 (관리 화면 미구현 → SQL 로 입력)
   - [ ] 특보 구역 키워드 매칭이 시·군 단위 특보(예: "부산(동부)")에서도 맞는지
   - [ ] 응답 지연·트래픽 한도(일일 호출 수) — 지역 수 × 하루 144회(10분 간격) 이내인지
4. 태풍 영향 예상 시각은 자동 추출하지 않는다 → 태풍 발생 시 관리자가 "태풍 영향 예상 시각 입력"으로 입력

## 보안
- [ ] `QR_SECRET`, `CRON_SECRET` 무작위 생성·비밀 저장소 보관
- [ ] 다중 인스턴스 배포 시 요청 횟수 제한을 Redis 기반으로 교체 (`packages/server/src/security.ts rateLimit`)
- [ ] 관리자 계정 2단계 인증 (미구현)
- [ ] 비밀번호 재설정 (미구현 — 이메일 발송 서비스 필요)
- [ ] 개인정보 보유기간 경과 데이터 파기 배치 (미구현)
- [ ] 위치 좌표가 GET 쿼리로 전달됨 → 액세스 로그 보관 정책 확인

## 시범 운영 지표 (정부지원사업·투자 자료용)
`ownerStats`·`adminOverview` 로 바로 뽑을 수 있는 값: 날씨별 예약 수, 방문 완료율(VISITED / 확정), 노쇼율, 할인 제공액(확정), 예약 금액 기반 추정 매출(추정치로 표기).
