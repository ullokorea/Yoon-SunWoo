# 청개구리 — 날씨 기반 오프라인 할인·예약 플랫폼 통합 개발 프롬프트

## 1. 역할 및 개발 목표

너는 15년 이상의 경험을 가진 시니어 풀스택 개발자이자 모바일 앱 UX/UI 디자이너, 서비스 기획자, 소프트웨어 아키텍트다.

지금부터 **'청개구리'라는 날씨 기반 오프라인 매장 할인·예약 플랫폼**을 실제 사업화가 가능한 수준의 MVP로 개발해 줘.

기획서만 작성하거나 화면 목업만 만드는 것이 아니라, 실제로 실행할 수 있는 애플리케이션을 구현하는 것이 목표다.

핵심 기능은 다음과 같다.

1. 비가 오는 지역에서 할인 혜택이 활성화된다.
2. 음식점과 카페 점주는 비 오는 날 적용할 할인율을 직접 설정한다.
3. 소비자는 주변 할인 매장을 탐색하고 예약할 수 있다.
4. 태풍 접근 예보 시 최대 50%의 특별 할인 프로모션을 준비할 수 있다.
5. 위험한 기상 상황에는 신규 방문 예약을 중단한다.
6. 태풍이 지나간 후 안전이 확인되면 특별 할인 예약을 제공한다.
7. 청개구리를 모티브로 한 독창적인 캐릭터와 브랜드 디자인을 적용한다.

서비스의 핵심 슬로건은 다음과 같다.

**"비가 오면, 혜택이 쏟아진다."**

## 2. 서비스 개요

### 서비스명
청개구리 (가칭)

### 서비스 유형
날씨 기반 O2O(Online to Offline) 할인 및 매장 예약 플랫폼

### 사업 목적

비 오는 날 오프라인 매장의 방문객과 매출이 감소할 수 있다는 문제를 해결하고자 한다.

소비자에게는 비가 오는 날 저렴하게 외식할 기회를 제공하고, 점주에게는 비 오는 날 발생하는 빈 좌석을 활용해 추가 매출을 창출할 기회를 제공한다.

장기적으로 소비자에게 다음과 같은 인식을 심어주는 것이 목표다.

**"비가 오는 날에는 청개구리 앱을 열어야 한다."**

### 주요 이용자

- 소비자: 20~30대 대학생, 직장인 및 합리적인 가격으로 외식을 즐기려는 사람
- 점주: 개인 음식점, 카페 및 소규모 오프라인 매장 운영자
- 관리자: 플랫폼 운영 및 제휴 매장 승인·관리 담당자

## 3. 개발 방식 및 기술 스택

다음 기술 스택을 우선 검토해 줘.

### 소비자 앱
- React Native + Expo
- TypeScript
- 모바일 우선 반응형 UI
- iOS 및 Android 지원

### 점주 관리자
- Next.js
- TypeScript
- Tailwind CSS
- 모바일 및 PC 반응형

### 플랫폼 관리자
- Next.js 기반 관리자 대시보드
- 점주 승인, 할인 관리, 예약 현황, 통계 기능

### 백엔드
- Supabase 또는 PostgreSQL 기반 백엔드
- 인증 및 권한 관리
- 예약 처리 API
- 날씨 판정 서비스
- 할인 정책 엔진
- 알림 서비스

### 외부 API
- 기상청 날씨·강수·태풍·기상특보 API
- 카카오맵 또는 네이버 지도 API
- 푸시 알림 서비스
- 추후 결제 서비스 연동이 가능한 구조

더 적합한 기술 스택이 있다면 이유를 설명하고 제안해도 좋다.

단, 실제 개발 환경에 적합하고 유지보수가 쉬우며, 초기 스타트업에서 운영할 수 있는 구조를 우선해야 한다.

**개발 환경의 실제 접근 권한과 사용 가능한 도구를 먼저 확인하고, 없는 API 키나 서비스 자격증명을 임의로 생성하지 마라.**

## 4. 브랜드 및 디자인 시스템

### 브랜드 콘셉트

비 오는 날을 좋아하는 귀여운 청개구리 캐릭터를 중심으로 디자인한다.

캐릭터는 단순한 장식이 아니라 서비스의 주요 브랜드 자산이다.

### 캐릭터

이름: 개굴이 (가칭)

특징:
- 초록색 청개구리
- 둥글고 귀여운 몸
- 크고 친근한 눈
- 노란색 우산
- 노란 장화 또는 우비
- 밝고 장난기 있는 표정
- 간결하고 기억하기 쉬운 실루엣

기존 유명 캐릭터를 모방하지 않고 독창적인 캐릭터를 디자인한다.

캐릭터는 날씨에 따라 다른 상태를 표현한다.

1. 맑은 날: 나뭇잎 아래에서 쉬고 있는 개굴이
2. 비 예보: 우산을 준비하는 개굴이
3. 비 오는 날: 신나게 뛰어다니는 개굴이
4. 태풍 접근: 실내에서 태풍을 대비하는 개굴이
5. 태풍 통과 후: 지역 상권을 응원하는 개굴이

캐릭터 애니메이션은 앱 성능을 저하시키지 않는 수준으로 적용한다.

### 디자인 방향

- 귀엽지만 유치하지 않은 디자인
- 한국의 20~30대 사용자가 선호할 만한 세련된 감성
- 현대적인 로컬 라이프스타일 서비스
- 직관적인 정보 구조
- 부드러운 모서리와 적절한 여백
- 높은 가독성
- 자연스러운 마이크로 인터랙션
- 할인 혜택이 눈에 띄는 UI

### 브랜드 색상

- 메인 그린: #45B96B
- 서브 옐로: #F6CD4B
- 라이트 민트: #DDF5EA
- 딥 포레스트: #263A32
- 기본 배경: #FFFFFF

색상은 디자인 시스템의 토큰으로 관리한다.

### 디자인 참고 방향

토스의 직관적인 사용성, 당근의 지역 친화적 경험, 현대적인 F&B 예약 서비스의 매장 탐색 경험을 참고하되 화면과 브랜드를 그대로 복제하지 않는다.

## 6. 날씨 기반 활성화 시스템

청개구리의 가장 중요한 기능이다.

### 기본 정책

앱 자체는 맑은 날에도 사용할 수 있지만, 일반적인 우천 할인 예약은 비가 오는 지역에서만 활성화한다.

### 맑은 날

- 앱 실행 가능
- 주변 제휴 매장 확인 가능
- 할인 혜택 미리 보기
- 즐겨찾기
- 비 알림 설정
- 일반 우천 할인 신규 예약 비활성화

메인 문구:

"개굴이가 비를 기다리고 있어요."

### 비 예보

- 비가 올 예정이라는 정보 표시
- 곧 열릴 할인 혜택 안내
- 관심 매장 할인 알림 신청
- 점주에게 프로모션 준비 알림

메인 문구:

"곧 혜택이 쏟아질 예정이에요!"

### 비 오는 날

- 할인 모드 활성화
- 할인 매장 목록 표시
- 할인율 및 가격 표시
- 예약 기능 활성화
- 사용자에게 알림 발송

메인 문구:

"비가 와요! 오늘의 할인이 열렸어요."

### 날씨 판정 로직

다음 사항을 구현한다.

1. 매장 위치를 기준으로 강수 상태 확인
2. 실시간 강수 관측과 단기 예보 활용
3. 지역별 할인 활성화 상태 관리
4. 기상 데이터 갱신 주기 관리
5. 날씨 상태 변경 이력 기록
6. 기상 API 장애 대응
7. 기존 확정 예약의 할인 조건 보존

비가 그치더라도 이미 확정된 예약은 원칙적으로 유지한다. 다만 안전상 위험이 발생하면 방문 일정 변경이나 취소를 지원한다.

날씨 데이터 갱신으로 할인 모드가 반복적으로 켜지고 꺼지지 않도록 최소 유지 시간 및 상태 전환 규칙을 설계한다.

## 7. 일반 우천 할인 기능

점주는 비 오는 날 적용할 할인 혜택을 직접 설정한다.

### 할인 설정 항목

- 할인율: 기본 실험 범위 10~30%
- 할인 적용 메뉴
- 할인 적용 시작 및 종료 시간
- 최대 할인 금액
- 최소 주문금액
- 예약 가능 인원
- 하루 최대 할인 예약 건수
- 자동 활성화 여부
- 할인 중단 여부

### 할인 유형

1. 전체 메뉴 할인
2. 특정 메뉴 할인
3. 세트 메뉴 할인
4. 특정 시간대 할인
5. 선착순 한정 할인

### 할인 정책

- 점주가 설정한 할인율만 적용한다.
- 할인율을 변경해도 기존 확정 예약의 조건은 유지한다.
- 실제 제공하지 않는 할인율을 표시하지 않는다.
- 정상가와 할인가를 명확히 표시한다.
- 할인 조건과 제한 사항을 예약 전에 안내한다.

## 8. 태풍 스페셜 프로모션

일반 우천 할인보다 높은 할인율을 제공하는 특별 이벤트를 개발한다.

### 프로모션명

**개굴이의 태풍 특가**

### 핵심 콘셉트

"태풍이 예고되면, 할인도 커진다!"

태풍 접근 예보 시 점주가 최대 50%의 특별 할인 혜택을 등록할 수 있도록 한다.

단, 태풍 발생 중 위험한 외출을 유도해서는 안 된다.

### 태풍 단계별 운영

#### 태풍 접근 예보 단계

- 태풍 스페셜 프로모션 준비
- 최대 50% 할인 등록
- 안전한 방문 시간대의 예약 제공
- 태풍 이후 방문 예약 접수
- 관심 사용자에게 특가 예고 알림

#### 태풍 영향권 및 위험 상황

- 기상특보 및 안전 상태 확인
- 위험 지역 신규 방문 예약 자동 제한
- 기존 예약 변경 및 취소 지원
- 안전 안내 메시지 제공
- 할인 혜택은 추후 이용할 수 있도록 보관

#### 태풍 통과 후

- 기상특보와 현장 안전 상태 확인
- 점주 영업 재개 여부 확인
- 안전한 지역의 예약 기능 재활성화
- 태풍 이후 회복 특가 제공
- 지역 상권 회복 캠페인 운영

### 할인 정책

- 일반 비: 10~30%
- 태풍 관련 특별 프로모션: 최대 50%
- 할인율은 점주가 설정
- 할인 수량 및 적용 메뉴 제한 가능
- 할인 적용 기간 설정 가능

### 안전 정책

태풍 강도가 높아질수록 할인 혜택을 무조건 높이는 구조로 개발하지 않는다.

기상특보, 강풍, 호우, 침수 위험 등 안전 조건을 반영해 방문 예약을 제어한다.

위험 여부가 불확실할 경우 신규 방문 예약을 제한하는 보수적인 정책을 적용한다.

태풍 특가의 핵심은 위험한 상황에 외출시키는 것이 아니라 **태풍 전후 안전한 시간에 방문 수요를 연결하는 것**이다.

## 19. 개발 진행 원칙

다음 순서로 작업해 줘.

### Step 1. 요구사항 분석

전체 요구사항을 분석하고 모호한 부분을 정리한다.

개발 진행을 막는 필수 질문만 먼저 요청하고, 나머지는 합리적인 기본값을 제안한다.

### Step 2. 아키텍처 설계

시스템 구조, 기술 스택, 폴더 구조, 데이터베이스, API를 설계한다.

### Step 3. UI/UX 설계

소비자 앱과 점주 관리자 화면을 설계한다.

화면은 실제 앱 수준의 완성도를 목표로 하며, 단순한 와이어프레임에서 끝내지 않는다.

### Step 4. 프로젝트 구현

실제 소스 코드를 작성하고 파일을 생성한다.

기능별로 나누어 개발하되, 기존 기능을 훼손하지 않도록 한다.

### Step 5. 통합 및 테스트

화면, API, 데이터베이스, 예약 로직을 연결한다.

테스트를 실행하고 발견한 오류를 수정한다.

### Step 6. 실행 및 검증

실행 가능한 환경이라면 앱을 실행하고 주요 사용자 흐름을 검증한다.

실행이 불가능한 환경에서는 실행하지 못한 항목과 그 이유를 명확히 설명한다.

### Step 7. 최종 결과 보고

완성된 기능, 미완성 기능, Mock으로 구현된 기능, 실제 운영 전 필요한 설정을 구분해 보고한다.

## 20. 반드시 지켜야 할 사항

- 기획서만 작성하고 개발을 끝내지 마라.
- 실제로 동작하는 앱을 목표로 해라.
- 화면만 만들어 놓고 기능이 구현되었다고 주장하지 마라.
- API 키, 결제 연동, 외부 데이터 연결 상태를 허위로 표시하지 마라.
- 사용자·점주·관리자 권한을 명확히 분리해라.
- 예약 수량과 할인 가격은 서버에서 검증해라.
- 날씨가 바뀌더라도 확정 예약의 조건을 보존해라.
- 위험한 태풍 상황에는 방문을 유도하지 마라.
- 모바일 UX를 최우선으로 고려해라.
- 코드는 재사용 가능하고 유지보수가 쉬워야 한다.
- 작업이 길어지면 단계별 진행 상황과 남은 작업을 명확히 정리해라.
- 불필요하게 복잡한 기능보다 실제 예약까지 이어지는 핵심 흐름을 우선 완성해라.

## 21. 최종 목표

이 프로젝트는 단순한 포트폴리오나 디자인 시연용 앱이 아니다.

실제 음식점 점주가 할인율을 설정하고, 소비자가 비 오는 날 주변 매장을 발견해 예약하며, 점주가 방문을 확인할 수 있는 서비스를 만드는 것이 목표다.

향후 정부지원사업 신청, 초기 투자 유치, 실제 상권 시범 운영까지 이어질 수 있도록 설계해 줘.

**지금부터 전체 요구사항을 분석하고, 개발에 필요한 핵심 결정 사항을 제시한 뒤 실행 가능한 MVP 구현을 시작해 줘.**
